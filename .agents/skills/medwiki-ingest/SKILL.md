# Ingest в med-wiki

Шаблон страницы — по таблице в начале `AGENTS.md`. Других шаблонов не используй, структуру не выдумывай.

| Вход | Раздел |
| --- | --- |
| Скан, фото, PDF меддокумента | «Меддокумент», с шага 0 |
| Готовый текст меддокумента | «Меддокумент», шаг 1 пропусти |
| Статья, транскрипт видео или лекции | «Статья» |
| «Добавь X в ключевые» | «Ключевые метрики» |
| Много файлов сразу | «Пакет» |

## Меддокумент

| Шаг | Действие |
| --- | --- |
| 0 | Найди в тексте дату и тип. Выбери имена `raw/images/...` и `raw/docs/...` по `.agents/skills/medwiki-file-naming/SKILL.md`. Даты в тексте нет — спроси дату, остальное имя не согласовывай. Файл с таким именем уже есть — добавь уточнение в тип, не перезаписывай |
| 1 | Сохрани оригинал в `raw/images/` |
| 2 | Распознай текст, сохрани в `raw/docs/`. Первой строкой — ссылка на оригинал(ы). Текст не исправляй и не дополняй. Нечитаемое — `[НЕЧИТАЕМО]`. Сомнительные даты, дозы, значения ключевых показателей перечисли в отчёте и попроси сверить со сканом |
| 3 | Тип: консультация, анализы, исследование, выписка |
| 4 | Каждый диагноз: создай или обнови `wiki/diagnoses/<slug>.md`. Обнови **Статус** — как сейчас по этому документу. В **Историю** — одна строка: дата, короткий факт, ссылка на `raw/docs/`. Новое сверху. Тот же факт той же даты не дублируй. Заключение целиком не копируй. Новый диагноз со статусом `active` или `monitoring` — добавь ссылку в строку нужного направления в **Активных направлениях** `wiki/profile/me.md`; подходящей строки нет — добавь строку. Диагноз стал `resolved` — убери его из направлений |
| 5 | Метрики — только из `wiki/metrics/_index.md` (раздел «Ключевые метрики»). Остальные цифры пропусти и пропуском не считай |
| 6 | Назначения и отмены — `wiki/profile/medications.md`. Нет активных препаратов — как сказано в шаблоне `medications.md`. Историю приёма не переноси |
| 7 | Новые аллергии — `wiki/profile/allergies.md`. Факторы риска, рост, вес, состав тела — `wiki/profile/me.md`; новое значение заменяет старое в строке, старое остаётся в `raw/docs/` |
| 8 | Назначенные визиты, обследования, вопросы врачу — в **Открытые вопросы** диагноза или жалобы и строкой в `wiki/profile/open-actions.md` со ссылкой. Без диагноза и жалобы — только строкой в `open-actions.md` со ссылкой на `raw/docs/`. Закрытое этим документом — удали. Препараты сюда не пиши |
| 9 | Каталоги `wiki/_index.md` и `wiki/*/_index.md`: ссылка и одна строка. В каталоге диагнозов — статус из шапки страницы |
| 10 | Отчёт в чат: какие сущности обновлены и что это меняет в картине; противоречия с уже записанным; что сверить со сканом. Без пересказа документа. Затем §H из `AGENTS.md` по изменениям |

По типу документа:

- Панель анализов — шаг 5; шаг 4, только если в заключении есть диагнозы.
- Консультация — шаги 4, 6, 8; шаг 5, если есть значения ключевых показателей.
- Исследование — шаги 4 и 8; шаг 5, только если есть измеримое значение из списка ключевых.
- Выписка — шаг 4 для каждого состояния, шаги 6 и 8. Период уже покрыт более полной выпиской — переноси только то, чего в wiki нет.

Запрещено: `wiki/visits/`, протокол приёма, пересказ анализа, копия тела документа, страница wiki на каждый документ.

## Ключевые метрики

Список ключевых показателей — только в `wiki/metrics/_index.md` (slug и название).

- Первое появление показателя из списка — создай `wiki/metrics/<slug>.md` по шаблону `metric.md`.
- **Динамика**: дата, значение, референс как в документе, статус (значения — в шаблоне), ссылка. Одна строка на дату. Та же дата и значение — пропусти; та же дата, другое значение — спроси пользователя, какое верно. `status` в шапке — по последнему значению.
- Показателя нет в списке — страницу не создавай.
- «Добавь X в ключевые» — строка в `wiki/metrics/_index.md`, страница с тегом `key-metric`, строки динамики из уже загруженных `raw/docs/`.

## Статья

1. Имя в `raw/articles/` выбери сам по `.agents/skills/medwiki-file-naming/SKILL.md` и сохрани.
2. `wiki/references/<slug>.md` по шаблону `reference.md`: источник, сжатые тезисы, явные связи с диагнозами пользователя.
3. Каталоги. В чат — короткое резюме.

Тезис статьи — не личный медицинский факт. Без связи с `wiki/diagnoses/` это справочный слой.

## Пакет

1. Пилот 3–5 файлов, список покажи пользователю до начала. В пилот включи по одному документу каждого типа, который есть в пакете: самую полную выписку, самую новую панель анализов, самую новую консультацию.
2. Lint по `.agents/skills/medwiki-lint/SKILL.md`.
3. Остальные пакетами по 10–15, lint после каждого.
