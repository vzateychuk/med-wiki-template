# Lint med-wiki

Запускает только пользователь.

## Структура и ссылки — исправь на месте

- **Каркас wiki.** Если нет обязательного файла — создай из шаблона (`AGENTS.md`, правило Missing skeleton file): `wiki/_index.md`, `wiki/profile/_index.md`, `wiki/profile/me.md`, `allergies.md`, `medications.md`, `open-actions.md`, каталоги `_index.md` в `diagnoses/`, `metrics/`, `symptoms/`, `notes/`, `references/`. Пустые каталоги — с правильной шапкой таблицы, без выдуманных строк.
- Сироты и битые ссылки — исправь путь или убери строку каталога, которая ведёт в никуда. Ссылку с `../` переведи в путь от корня.
- Файл `raw/docs/` из скана ссылается на существующий оригинал в `raw/images/`.
- Каталоги `_index.md` и файлы в папке согласованы:
  - обычные каталоги — каждая страница есть в `_index.md`, лишних строк нет;
  - `wiki/diagnoses/_index.md` — статус в строке = шапка страницы; порядок: active, monitoring, resolved;
  - `wiki/metrics/_index.md` — колонки **slug / Название / Страница** (шаблон `index.md`, блок про показатели). Файл `wiki/metrics/<slug>.md` без строки в каталоге — добавь строку. Строка с slug, но без файла / с пустой «Страница» — **не удаляй**; создай страницу по ingest (схема А) и заполни ссылку.
- История диагноза: новое сверху.
- На странице диагноза нет раздела «Открытые вопросы» — если остался, перенеси ещё актуальные дела в `open-actions.md` по правилам синтеза (ingest, шаг 8) и удали раздел.
- **Активные направления** в `wiki/profile/me.md`: ссылки ведут на существующие страницы; каждый диагноз `active` или `monitoring` есть ровно в одном направлении; диагнозов `resolved` там нет.
- **Связи диагноз ↔ метрика симметричны.** Каждой строке в «Связанные метрики» диагноза соответствует строка в «Связанные диагнозы» страницы метрики, и наоборот. Ссылку на несуществующую страницу исправь (создай страницу метрики по ingest, шаг 5, или убери строку). Пустой раздел — не ошибка, если источник показатель не назначал; назначал — заполни по ingest, шаг 4. Не выдумывай связь.
- **Теги диагноза непусты** (`tags: []` — ошибка): 1–3 тега по ingest, шаг 4; у `resolved`-диагноза есть тег `resolved`.
- **Старые страницы** (пустые «Связанные метрики», пустые `tags`) — дозаполни по ingest (раздел «Страницы, созданные до этих правил»), существующие строки не перезаписывай.
- Страница не по своему шаблону (какой — в таблице в начале `AGENTS.md`) — приведи к шаблону, факты не теряй.
- Поле `type` в YAML-шапке страницы совпадает с шаблоном этой папки:

  | Папка | Ожидаемый `type` | Шаблон |
  | --- | --- | --- |
  | `wiki/diagnoses/` | `condition` | `diagnosis.md` |
  | `wiki/metrics/` | `lab` | `metric.md` |
  | `wiki/symptoms/` | `symptom` | `symptom.md` |
  | `wiki/references/` | `reference` | `reference.md` |
  | `wiki/notes/` | `note` | `note.md` |
  | `wiki/profile/me.md` | `profile` | `me.md` |
  | `wiki/profile/allergies.md` | `allergies` | `allergies.md` |
  | `wiki/profile/medications.md` | `regimen` | `medications.md` |

  Неверно — исправь `type` (факты не трогай). У `_index.md` и `open-actions.md` поля `type` нет.

## Сверка wiki с raw — приведи wiki к последнему документу

- `wiki/diagnoses/` против последних `raw/docs/`. Диагноз упомянут в raw, страницы нет — создай.
- `wiki/profile/medications.md` против последних консультаций: назначен, отменён, доза.
- Реестр `wiki/sources/_index.md` против `raw/docs/`: файл есть, строки нет — не загружен, перечисли в отчёте (не создавай строку сам и не запускай ingest без просьбы); строка ведёт на несуществующий файл — битая ссылка. Реестр отсутствует — создай по шаблону `index.md`.
- Показатель есть в панели `raw/docs/`, а страницы в `wiki/metrics/` нет — создай/обнови по правилам ingest (схема А, синонимы). Строки динамики не хватает, только если у значения в тексте есть полный день забора (правила дня — ingest, «Динамика», пункты 1–5) и на странице нет пары (этот день + это значение). Дату в имени файла и дату визита второй строкой не добавляй. Прошлый результат без полного дня (только год или даты нет) — не недостающая строка.
- На странице метрики две строки с одной датой и **заметно разными** значениями/референсами — подозрение на склейку разных показателей (как АЧТВ и Ratio). Сверь исходные имена в `raw/docs/`; при разных именах — раздели slug по словарю, не оставляй обе строки на одной странице.
- `wiki/profile/open-actions.md` — правила таблицы берутся только из шага 8 ingest (фильтр попадания, возврат из Мониторинга, возраст строки, порядок строк); здесь они не повторяются и не переопределяются. Проверка работает с **текущей таблицей**, не пересобирает её заново из документов:
  - просроченное, устаревшее по возрасту и дубли — покажи списком и удали только после «да» пользователя (по каждой строке или по всему списку); при «оставить» спроси новый срок (шаг 8, п. 6);
  - возьми самый свежий документ каждого профиля (тип + специализация, шаг 8 п. 5) и найди дела, которые проходят фильтр шага 8, но отсутствуют в таблице и не помечены «закрыто пользователем» в **Мониторинге**. Не добавляй молча и не пропускай: по каждому спроси, добавить в таблицу или закрыть как неактуальное; закрытое — в **Мониторинг** по правилу шага 8;
  - дела из более старых документов своего профиля заново не предлагай;
  - в отчёте — удалённое после подтверждения, оставленное с новым сроком, ответы по найденным делам.

## Только список пользователю, без правок

- Имена в `raw/` не по `.agents/skills/medwiki-file-naming/SKILL.md`: запусти `naming.py check --layer raw_docs --dir raw/docs` (и `raw_images`, `raw_articles`). Не переименовывай. Файлы с разными именами, но одной датой и одним текстом — возможный дубль документа: перечисли в отчёте.
- Имена в `wiki/notes/` — формат `YYYY-MM-DD-<slug>.md`; в `wiki/symptoms/` — `<slug>.md` без даты (см. навык имён). Неверное имя — только в отчёт, не переименовывай сам.
- Противоречия между двумя документами в `raw/docs/` — не выбирай сам, какой верен.

## Результат

Правки в `wiki/` на месте и короткий отчёт в чате: что сошлось, что исправлено, что осталось.

Запрещено: файлы отчётов в wiki, метки `[BROKEN_LINK]` и `[REQUIRES_VERIFICATION]` вместо починки.
