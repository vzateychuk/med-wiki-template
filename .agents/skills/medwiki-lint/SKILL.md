# Lint med-wiki

Запускает только пользователь («проверь wiki», «lint»), кроме случая: маршрут Q не нашёл страницу показателя при наличии анализов в `raw/docs/` — тогда сразу «Пересборка метрики» ниже для этого slug, без полного прохода. Отдельной команды «пересобери метрику» у пользователя нет: полный lint сам чинит нужные показатели.

## Пересборка метрики

Внутренняя процедура (полный lint или автозапуск с Q). Не замена ingest: первичное заведение с **новой** панели — шаг 5 ingest. Здесь — ремонт уже лежащего `raw/`.

**Когда:** страница отсутствует при значениях в `raw/docs/`; динамика явно неполная относительно загруженных панелей; рассинхрон имён после расширения словаря синонимов. На полном lint — все такие slug; на автозапуске с Q — только запрошенный.

**Что сделать:** пересобери страницу `wiki/metrics/<slug>.md` и строки **Динамики** из **всех** уже загруженных `raw/docs/`, где показатель встречается под любым синонимом того же slug (резолвер + `schema/metric-synonyms.yaml`; только точное совпадение; Ratio / % / абсолют / разный биоматериал — разные slug). Каталог `wiki/metrics/_index.md` — строка slug / название / страница. Шаблон — `metric.md`.

**День забора** (колонка «Дата», `YYYY-MM-DD`) — в таком порядке:
1. В сводке лабораторных результатов строка `_Дата:` под группой — один день на всю группу.
2. В «Предыдущих обследованиях» дата в скобках у названия — день этой строки.
3. Дата в тексте значения («от 01.12.25») — этот день; двузначный год — по году документа.
4. Документ-анализы (или измеримое в исследовании), отдельного дня нет — день бланка (дата события из текста файла).
5. Консультация, измерение на этом визите, отдельного дня нет — дата визита.
6. Консультация приводит **прошлый** результат без полного дня (только год или даты нет) — строку **не** пиши и страницу из одного такого упоминания **не** создавай.

Две разные даты события в тексте и неясно, какая день бланка/визита — строку не пиши, оба варианта в отчёт lint. Дата в имени файла и дата визита второй строкой не добавляй. УЗИ / рентген / денситометрия — не метрики.

**Строка динамики:** значение и референс как в документе; статус: норма → `normal`, повышен/выше → `elevated`, понижен/ниже → `low`, пограничный → `borderline`, сравнить не с чем → `unknown`. Одна строка на пару (день + исходное имя). Та же дата и то же значение — пропусти. Два разных имени с одной панели на один slug — раздели slug, не пиши обе на одну страницу. `status` в шапке — по последней строке. ПЦР/мазок «обнаружено–не обнаружено» → `qualitative`; аллерген панели со своим значением → `panel-item`.

## Структура и ссылки — исправь на месте

- **Каркас wiki.** Нет обязательного файла — создай из шаблона по правилу Missing skeleton file (`AGENTS.md`, там же список файлов). Пустые каталоги — с правильной шапкой таблицы, без выдуманных строк.
- Сироты и битые ссылки — исправь путь или убери строку каталога, которая ведёт в никуда. Ссылку с `../` переведи в путь от корня.
- Файл `raw/docs/` из скана ссылается на существующий оригинал в `raw/images/`.
- Каталоги `_index.md` и файлы в папке согласованы:
  - обычные каталоги — каждая страница есть в `_index.md`, лишних строк нет;
  - `wiki/diagnoses/_index.md` — статус в строке = шапка страницы; порядок: active, monitoring, resolved;
  - `wiki/metrics/_index.md` — колонки **slug / Название / Страница** (шаблон `index.md`, блок про показатели). Файл `wiki/metrics/<slug>.md` без строки в каталоге — добавь строку. Строка с slug, но без файла / с пустой «Страница» — **не удаляй**; создай страницу по «Пересборка метрики» выше и заполни ссылку.
- История диагноза: новое сверху.
- На странице диагноза нет раздела «Открытые вопросы» — если остался, перенеси ещё актуальные дела в `open-actions.md` по правилам синтеза (ingest, шаг 8) и удали раздел.
- **Активные направления** в `wiki/profile/me.md`: ссылки ведут на существующие страницы; каждый диагноз `active` или `monitoring` есть ровно в одном направлении; диагнозов `resolved` там нет.
- **Связи диагноз ↔ метрика симметричны.** Каждой строке в «Связанные метрики» диагноза соответствует строка в «Связанные диагнозы» страницы метрики, и наоборот. Ссылку на несуществующую страницу метрики исправь («Пересборка метрики» выше) или убери строку. Пустой раздел — не ошибка, если в документе-источнике показатель для этого диагноза не назван; назван — дозаполни связь из того документа, не выдумывай.
- **Теги диагноза непусты** (`tags: []` — ошибка): 1–3 тега по ingest, шаг 4; у `resolved`-диагноза есть тег `resolved`.
- **Старые страницы** (пустые «Связанные метрики», пустые `tags`) — дозаполни по ingest (раздел «Страницы, созданные до этих правил»), существующие строки не перезаписывай.
- Страница не по своему шаблону (какой — в таблице в начале `AGENTS.md`) — приведи к шаблону, факты не теряй.
- Поле `type` в YAML-шапке страницы совпадает с шаблоном этой папки:

  | Папка | Ожидаемый `type` | Шаблон |
  | --- | --- | --- |
  | `wiki/diagnoses/` | `condition` | `diagnosis.md` |
  | `wiki/metrics/` | `lab` | `metric.md` |
  | `wiki/symptoms/` | `symptom` | `symptom.md` |
  | `wiki/references/` | `reference` | `reference.md` |
  | `wiki/notes/` | `note` | `note.md` |
  | `wiki/profile/me.md` | `profile` | `me.md` |
  | `wiki/profile/allergies.md` | `allergies` | `allergies.md` |
  | `wiki/profile/medications.md` | `regimen` | `medications.md` |

  Неверно — исправь `type` (факты не трогай). У `_index.md` и `open-actions.md` поля `type` нет.

## Сверка wiki с raw — приведи wiki к последнему документу

- `wiki/diagnoses/` против последних `raw/docs/`. Диагноз упомянут в raw, страницы нет — создай.
- `wiki/profile/medications.md` против последних консультаций: назначен, отменён, доза.
- Реестр `wiki/sources/_index.md` против `raw/docs/`: файл есть, строки нет — не загружен, перечисли в отчёте (не создавай строку сам и не запускай ingest без просьбы); строка ведёт на несуществующий файл — битая ссылка. Реестр отсутствует — создай по шаблону `index.md`.
- Показатель есть в панели `raw/docs/`, а страницы в `wiki/metrics/` нет — «Пересборка метрики» выше для этого slug. Строки динамики не хватает, только если у значения есть полный день забора (пункты 1–5 там же) и на странице нет пары (этот день + это значение). Пункт 6 (прошлый результат без полного дня) — не недостающая строка.
- На странице метрики две строки с одной датой и **заметно разными** значениями/референсами — подозрение на склейку разных показателей (как АЧТВ и Ratio). Сверь исходные имена в `raw/docs/`; при разных именах — раздели slug по словарю, не оставляй обе строки на одной странице.
- `wiki/profile/open-actions.md` — правила таблицы берутся только из шага 8 ingest (фильтр попадания, возврат из Мониторинга, удаление только по слову пользователя, порядок строк); здесь они не повторяются и не переопределяются. Проверка работает с **текущей таблицей**, не пересобирает её заново из документов:
  - дубли (шаг 8, п. 5) — покажи списком и удали только после «да» пользователя. Дата в **Срок** и возраст источника — не повод удалять строку или спрашивать о ней (шаг 8, п. 6);
  - **Пересказ вместо ссылки.** Если в ячейке строки развёрнутый текст (перечень, обоснование), а в `wiki/notes/_index.md` или `wiki/references/_index.md` есть страница на эту тему — предложи заменить текст ссылкой на неё; правка только после «да». Страницы нет — ничего не предлагай;
  - возьми самый свежий документ каждого профиля (тип + специализация, шаг 8 п. 5) и найди дела, которые проходят фильтр шага 8, но отсутствуют в таблице и не помечены «закрыто пользователем» в **Мониторинге**. Не добавляй молча и не пропускай: по каждому спроси, добавить в таблицу или закрыть как неактуальное; закрытое — в **Мониторинг** по правилу шага 8;
  - дела из более старых документов своего профиля заново не предлагай;
  - в отчёте — удалённое после подтверждения, ответы по найденным делам.

## Только список пользователю, без правок

- Имена в `raw/` не по `.agents/skills/medwiki-file-naming/SKILL.md`: запусти `naming.py check --layer raw_docs --dir raw/docs` (и `raw_images`, `raw_articles`). Не переименовывай. Файлы с разными именами, но одной датой и одним текстом — возможный дубль документа: перечисли в отчёте.
- Имена в `wiki/notes/` — формат `YYYY-MM-DD-<slug>.md`; в `wiki/symptoms/` — `<slug>.md` без даты (см. навык имён). Неверное имя — только в отчёт, не переименовывай сам.
- Противоречия между двумя документами в `raw/docs/` — не выбирай сам, какой верен.

## Результат

Правки в `wiki/` на месте и короткий отчёт в чате: что сошлось, что исправлено, что осталось.

Запрещено: файлы отчётов в wiki, метки `[BROKEN_LINK]` и `[REQUIRES_VERIFICATION]` вместо починки.
