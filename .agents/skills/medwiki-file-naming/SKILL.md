# Имена файлов

Имя нового файла выбирай сам по правилам ниже. Пользователя не спрашивай. Существующий файл не переименовывай и не перезаписывай: при занятом имени добавь уточняющее слово в тип или slug.

## `raw/docs/` — текст меддокумента

`YYYY-MM-DD_<тип>.md`. Проверка: `^\d{4}-\d{2}-\d{2}_[a-z0-9-]+\.md$`.

- Дата — дата документа из его текста, не дата загрузки. Даты в тексте нет — предложи дату и спроси.
- Два документа одного типа в один день — уточняющее слово: `2025-11-22_cardiology-consultation.md`.

| Суффикс | Содержимое |
| --- | --- |
| `*-consultation.md` | Консультация |
| `*-lab-panel.md` | Лабораторные анализы |
| `*-discharge.md` | Выписка |
| `*-ultrasound.md`, `*-mri.md`, `*-xray.md`, `*-ecg.md`, `*-histology.md`, `*-colonoscopy.md` | Инструментальные исследования |

## `raw/images/` — оригинал

То же базовое имя, что у файла в `raw/docs/`, исходное расширение. Несколько страниц — `-p1`, `-p2`: `2025-11-22_lab-panel-p1.jpg`.
Проверка: `^\d{4}-\d{2}-\d{2}_[a-z0-9-]+\.[a-z0-9]+$`.

## `raw/articles/` — статьи и транскрипты

`YYYY-MM-DD-<slug>.md`, дата — дата материала или загрузки.
Проверка: `^\d{4}-\d{2}-\d{2}-[a-z0-9]+(-[a-z0-9]+)*\.md$`.

## Страницы wiki

`<slug>` — латиница и цифры, слова через дефис (kebab-case).

| Что | Имя | Проверка |
| --- | --- | --- |
| Диагноз | `wiki/diagnoses/<slug>.md` | `^[a-z0-9]+(-[a-z0-9]+)*\.md$` |
| Ключевой показатель | `wiki/metrics/<slug>.md` | `^[a-z0-9]+(-[a-z0-9]+)*\.md$` |
| Справочная страница | `wiki/references/<slug>.md` | `^[a-z0-9]+(-[a-z0-9]+)*\.md$` |
| Заметка | `wiki/notes/YYYY-MM-DD-<slug>.md` — дата создания | `^\d{4}-\d{2}-\d{2}-[a-z0-9]+(-[a-z0-9]+)*\.md$` |
| Жалоба без документа | `wiki/symptoms/YYYY-MM-DD-<slug>.md` — дата жалобы | `^\d{4}-\d{2}-\d{2}-[a-z0-9]+(-[a-z0-9]+)*\.md$` |

Каталоги `_index.md` проверке не подлежат.
