# Таблица дел `open-actions.md`

Дела пользователя — только в файле `wiki/profile/open-actions.md`. Из документа — синтез, не копирование строк.

Этот навык — единственный источник правил составления таблицы дел. Ingest, маршруты Q и S в `AGENTS.md` и проверка базы (`medwiki-lint`) ссылаются сюда и правила не повторяют.

**Блок «нужно уточнить»** ниже — на ingest это блок шага 10 ingest; на других маршрутах — вопрос пользователю в ответе или в отчёте lint.

Пиши только дела пользователя: визит, обследование, «Начать приём …» со ссылкой на `/wiki/profile/medications.md`.  
Не пиши: вопросы врачу, дозы и схему препаратов (схема — в `medications.md`), размытые ярлыки без глагола.

Если дело описано в файле (документ, заметка, справочник), в строке даётся ссылка на этот файл, а не пересказ. Текст в ячейке допустим, если описывающего файла нет или пользователь сам так просит.

**Фильтр попадания в таблицу.** Число строк не ограничено: в таблице столько дел, сколько проходит фильтр. Фильтр действует только на дела, которые агент сам извлекает из документа. Дело, которое пользователь назвал своим планом («мне надо сдать…», «добавь в дела»), записывается как есть.
- В таблицу идёт разовый конкретный шаг (визит, обследование, «Начать приём …»), который врач назначил или рекомендовал и который ещё не выполнен. Не подходит: «рекомендуется контроль», «при необходимости».
- Всё остальное — регулярное, «контроль через N месяцев» без конкретного шага, необязательное, низкоприоритетное — в **Мониторинг** страницы диагноза, не в open-actions.
- **Запись в Мониторинг:** со ссылкой на документ-источник (`/raw/docs/…`). Если пользователь закрыл дело как неактуальное — с пометкой «закрыто пользователем».
- **Возврат из Мониторинга в таблицу** — только если вышел более новый документ **того же профиля** (п. 5), который подтверждает, что дело нужно сделать, или по прямой просьбе пользователя. Дело без пометки «закрыто пользователем» при проверке базы можно предложить вернуть, если оно проходит фильтр. Дело с пометкой «закрыто пользователем» при проверке базы не предлагается.

1. **Группируй** — связанные обследования (один визит / одна проба / один день) = одна строка.
2. **Действие** — коротко: глагол + объект («Сдать…», «Записаться…», «Сделать УЗИ…», «Начать приём…»); подготовка или место — одна короткая фраза в той же ячейке («натощак», «после УЗИ»). Подробности — ссылкой на файл.
3. **Срок** — `YYYY-MM-DD` или «не указан»; только следующий конкретный шаг.
4. **Размытое** («Инсулин») — не добавляй; если ясно из документа — сформулируй сам, иначе в блок «нужно уточнить».
5. **Закрытие и дедуп** — новый документ **того же профиля**, который, судя по тексту, закрывает дело из более старого документа того же профиля, строку **не удаляет**: добавь в блок «нужно уточнить» «похоже, выполнено: …. Убрать?»; затем добавь синтез из нового. Один смысл = одна строка (оставь более конкретную / с ясным сроком); дубли убирай без вопросов — это не закрытие дела.

   **Профиль документа** — не «все `consultation` подряд». Это пара:

   | Часть | Откуда взять |
   | --- | --- |
   | Тип | Суффикс типа в имени файла: `consultation`, `lab-panel`, `discharge`, `ultrasound`, … |
   | Специализация | 1) disambiguator в имени после типа (`…_consultation-allergist.md`, `…_consultation-lor.md` → `allergist` / `lor`); число в конце не учитывается (`…_consultation-allergist-2.md` → `allergist`); 2) если в имени нет — специальность/отделение из тела («аллерголог», «ЛОР», «эндокринолог»); 3) нет ни там ни там — специализация пустая |

   Примеры: `consultation/allergist` и `consultation/lor` — **разные** профили (новая консультация аллерголога не закрывает дела от ЛОРа). Два файла `consultation/allergist` — один профиль. Два `lab-panel` без специализации — один профиль `lab-panel`. Выписка `discharge` не закрывает дела из консультаций.

6. **Удаление строки** — только после явного слова пользователя («сделал», «неактуально»). По дате в **Срок** и по возрасту источника дела не удаляются и кандидатами не предлагаются; просроченный срок — просто дата в таблице.
7. **Таблица** — одна; строки идут по сроку: ближайшие сверху, «не указан» в конце; при равном сроке порядок не важен. **Причина** — ссылка на диагноз, если он есть; иначе короткая фраза или ссылка на файл. **Источник** — ссылка на файл, откуда дело: `/raw/docs/…`, `/wiki/notes/…`, `/wiki/references/…`; для дела со слов пользователя — «со слов пользователя».
