# med-wiki: концепция LLM Wiki для медицинского консультанта

> **Канон для человека.** Как устроена база и зачем.
> Норматив для агента — `AGENTS.md` и навыки в `.agents/skills/` (раздел 9). При конфликте с этим файлом приоритет у них.
> Имена файлов — `.agents/skills/medwiki-file-naming/SKILL.md`. Шаблоны страниц — `schema/templates/`.

## 1. Цель

Персональная база знаний о здоровье, с которой работает AI-консультант:

- профиль и суммарные показатели — синтез, а не копия документов;
- оригиналы меддокументов и их распознанный текст — со ссылками из wiki;
- текущее состояние, открытые действия, история болезней;
- динамика ключевых показателей;
- подготовка к визитам и вопросы врачам;
- внешние материалы (статьи, транскрипты) — отдельно от личных фактов.

Агент работает в двух ролях:

- **Консультант** (по умолчанию) — отвечает по досье. Сначала определяет тип вопроса, потом читает только нужные страницы.
- **Maintainer** — загружает документы (ingest), проверяет базу (lint), сохраняет итоги консультаций.

## 2. Два слоя

```
raw/   = входящие: оригинал документа, его распознанный текст, статья. Записанный файл не меняется.
wiki/  = что актуально сейчас: диагноз на всю историю, ряд показателя, схема, открытые действия.
```

Главный принцип: **картина состояния пользователя складывается только из `wiki/`.** `raw/` — сырьё для синтеза. Агент заглядывает в распознанный документ при ответе, только чтобы дать точную цитату врача или цифру, которой нет в wiki, но не строит по нему выводов в обход wiki.

Кто пишет в `raw/`: агент при загрузке документа сам выбирает имя по навыку имён, сохраняет оригинал в `raw/images/` и распознанный текст в `raw/docs/`. Существующие файлы в `raw/` агент не меняет. Исключение — ошибка распознавания, которую пользователь просит исправить по скану.

| Вопрос | Где ответ |
| --- | --- |
| Оригинал документа (скан, фото, PDF) | `raw/images/` |
| Что написано в конкретном анализе или заключении | `raw/docs/` — агент читает для цитаты, в wiki это не копируется |
| Как сейчас заболевание | `wiki/diagnoses/<slug>.md`, секция **Статус** |
| Как показатель менялся | `wiki/metrics/<slug>.md`, одна строка на дату |
| Что принимаю | `wiki/profile/medications.md` |
| Что не сделано | `wiki/profile/open-actions.md` |
| Аллергии, направления наблюдения | `wiki/profile/` |
| Что решили на прошлой консультации | `wiki/notes/` |
| Чужой протокол, статья, транскрипт | `wiki/references/` — общие знания, не личный факт |

Загрузка документа **не создаёт** в wiki копию консультации, анализа или исследования. Документ остаётся файлом в `raw/docs/`. В wiki обновляются только сквозные сущности: статус диагноза и одна строка его истории, строка ключевого показателя, схема препаратов, открытые действия.

Отчёт, который пользователь просит сформировать (например, «паратгормон за 5 лет»), — это представление уже имеющихся данных, а не новый факт. Агент спрашивает, куда его сохранить, и не кладёт его ни в `wiki/`, ни в `raw/`, чтобы производный файл потом не стал «источником».

## 3. Именование

Документ и сущность называются по-разному: документ — по дате события, сущность — без даты, потому что живёт всю историю.

| Что | Формат | Пример |
| --- | --- | --- |
| Распознанный меддокумент | `raw/docs/YYYY-MM-DD_<тип>.md` | `2025-11-22_lab-panel.md` |
| Оригинал меддокумента | `raw/images/` — то же имя, исходное расширение; страницы `-p1`, `-p2` | `2025-11-22_lab-panel-p1.jpg` |
| Статья или транскрипт | `raw/articles/YYYY-MM-DD-<slug>.md` | `2026-06-22-vitamin-d-overview.md` |
| Диагноз, метрика, справочная страница | `wiki/.../<slug>.md` без даты в имени | `wiki/diagnoses/insulin-resistance.md` |
| Жалоба без документа, заметка | `wiki/symptoms/` и `wiki/notes/` — `YYYY-MM-DD-<slug>.md` | `wiki/notes/2026-07-01-pth-trend.md` |

Дата в имени меддокумента — дата документа из его текста, не дата загрузки. Если даты в тексте нет, агент предлагает дату и спрашивает — это единственный случай, когда имя зависит от ответа пользователя. Имя нового файла агент выбирает сам по навыку; существующие файлы не переименовывает. Точные правила — `.agents/skills/medwiki-file-naming/SKILL.md`.

Ссылки между файлами пишутся от корня репозитория с начальным `/` (например, `/raw/docs/2025-11-22_lab-panel.md`). Так ссылка не ломается, если страницу или шаблон перенести в другую папку.

## 4. Файловая структура

```
<корень>/
├── AGENTS.md            # ядро правил агента
├── .agents/skills/
│   ├── medwiki-ingest/  # загрузка документов и статей
│   ├── medwiki-lint/    # проверка базы
│   └── medwiki-file-naming/ # имена файлов
├── raw/
│   ├── images/          # оригиналы меддокументов
│   ├── docs/            # распознанный текст меддокументов
│   └── articles/        # статьи и транскрипты
├── wiki/
│   ├── _index.md        # короткий маршрутизатор
│   ├── profile/
│   │   ├── _index.md
│   │   ├── me.md
│   │   ├── allergies.md
│   │   ├── medications.md
│   │   └── open-actions.md
│   ├── diagnoses/
│   ├── metrics/
│   ├── symptoms/
│   ├── references/
│   └── notes/
└── schema/
    ├── concept.md
    └── templates/
```

## 5. Что лежит в wiki

| Папка или файл | Что это |
| --- | --- |
| `profile/me.md` | Кто пользователь, факторы риска, **активные направления** (кардиология, эндокринология и т.д.) со ссылками |
| `profile/allergies.md` | Аллергии |
| `profile/medications.md` | Только текущая схема. История приёма остаётся в `raw/docs/` |
| `profile/open-actions.md` | Незакрытые визиты, обследования и вопросы врачам. Не препараты. Приоритет: срочно, планово, можно отложить |
| `diagnoses/<slug>.md` | Одно заболевание на всю историю. **Статус** — как сейчас. **История** — таблица, новое сверху, каждая строка ссылается на `raw/docs/` |
| `metrics/_index.md` | Список ключевых показателей этого экземпляра базы |
| `metrics/<slug>.md` | Один показатель: таблица дата / значение / референс / источник |
| `symptoms/` | Жалоба без меддокумента |
| `references/` | Синтез статьи или транскрипта. Не личный факт без явной связи с диагнозом |
| `notes/` | Сохранённые итоги консультаций (по фразе «сохрани в wiki»): выводы, решения, вопросы врачу. Учитываются в следующих консультациях |
| `_index.md` в папке | Каталог: ссылка, одна строка описания, статус. Не копия тела страницы |

«Активные направления» в `me.md` — точка входа консультации. Агент ведёт их сам: новый диагноз добавляет в нужное направление, разрешённый (`resolved`) — убирает. Для каждого файла профиля и для каталогов есть шаблон в `schema/templates/`.

Открытые действия рождаются в секции **Открытые вопросы** диагноза или жалобы. `open-actions.md` — их сводный список; действие без диагноза записывается туда напрямую со ссылкой на документ. Выполненное удаляется, а не помечается «сделано».

Ключевые показатели задаёт человек в `wiki/metrics/_index.md`. Остальные цифры панели анализов в wiki не переносятся: агент берёт их из `raw/docs/` для ответа, когда о них спрашивают. Если о показателе спрашивают второй раз за диалог или просят его динамику — агент предложит сделать его ключевым.

## 6. Как агент выбирает, что читать

До чтения досье агент относит запрос к одному маршруту.

| Код | Когда | Что читает |
| --- | --- | --- |
| **P** — личный факт | «мой», показатель, диагноз, дата анализа | каталог, нужные страницы; точную цифру или цитату — из `raw/docs/` |
| **H** — консультация | «можно ли мне», питание, тренировки, добавки, самочувствие | профиль, схема; аллергии — если вопрос про препарат, добавку или продукт; затем только нужное активное направление |
| **G** — общая теория | вопрос без привязки к пользователю | досье не читает; знания модели и веб |
| **O** — что не сделано | «что не закрыто», подготовка к визиту | сначала `open-actions.md` |
| **S** — сохранение | «сохрани в wiki», «запиши жалобу», «сохрани отчёт» | заметка, жалоба или файл отчёта вне базы |
| **I** — загрузка | «загрузи», «обработай», файл документа или статьи | ingest документа или статьи |
| **K** — ключевые показатели | «добавь X в ключевые» | список в `wiki/metrics/_index.md` и страница показателя |
| **R** — правило | «запомни правило», «всегда делай …» | спрашивает, навсегда или на этот диалог; навсегда — правит одно место в инструкциях после согласия |
| **L** — проверка | «проверь wiki», «lint» | вся структура wiki против `raw/docs/` |

Если по формулировке непонятно, что нужно, агент задаёт один уточняющий вопрос и не отвечает наугад. Запрос из нескольких целей («загрузи анализ и скажи, что изменилось») выполняется по порядку: сначала загрузка, потом консультация.

Если в жалобе или документе есть признаки состояния, требующего срочной помощи, агент начинает ответ с рекомендации срочно обратиться к врачу. Агент не ставит новых диагнозов и не меняет назначения врача.

## 7. Потоки

### Загрузка меддокумента

```
скан/фото/PDF ──► raw/images/  (оригинал; имя выбирает агент)
                     │  распознавание текста
                     ▼
                  raw/docs/    (текст как есть, нечитаемое помечено)
                     │  синтез
                     ▼
диагноз (статус + строка истории) · строка ключевой метрики · схема · аллергии · открытые действия
                     │
                     ▼
каталоги _index.md · отчёт в чат · консультация по изменениям
```

Если пользователь даёт готовый текст, шаг с оригиналом пропускается. Сомнительные после распознавания даты, дозы и значения агент перечисляет и просит сверить со сканом.

### Жалоба или вопрос

Маршрут из раздела 6. Ответ со ссылкой на файл. Чего в источниках нет — не утверждать. Новую жалобу агент предлагает записать в `wiki/symptoms/`.

### Статья или транскрипт

Файл в `raw/articles/`, синтез в `wiki/references/`. В ответ о личном анализе или диагнозе этот слой не подставляется вместо досье.

### Lint

Запускает пользователь. Агент сверяет wiki с последними документами, чинит ссылки и каталоги на месте, пересобирает открытые действия и пишет отчёт в чат. Неверные имена файлов и противоречия между двумя документами агент только перечисляет — решает пользователь. Файлы отчётов в wiki не создаются, пояснения терминов в страницы досье не дописываются.

## 8. Рост

Wiki растёт медленнее `raw/`. Не копировать тела консультаций. Не заводить страницу на каждый показатель панели. Длинный сохранённый ответ (больше примерно 4 КБ) класть в `references/`, в `notes/` оставлять указатель.

## 9. Как устроены инструкции агента

Инструкции агента занимают место в контексте модели — в тексте, который модель видит при каждом ответе. Чем больше постоянная часть, тем дороже каждый шаг. Поэтому инструкции разделены:

| Файл | Когда агент его читает | Что внутри |
| --- | --- | --- |
| `AGENTS.md` | Всегда, с начала сессии | Роль, безопасность, права на запись, два слоя, выбор маршрута, консультация, сохранение |
| `.agents/skills/medwiki-ingest/SKILL.md` | Только при загрузке документа или статьи | Шаги ingest, ключевые метрики, пакетная загрузка |
| `.agents/skills/medwiki-lint/SKILL.md` | Только при проверке базы | Список проверок lint |
| `.agents/skills/medwiki-rules/SKILL.md` | Только когда пользователь просит запомнить или изменить правило | Куда и как записать правило |
| `.agents/skills/medwiki-file-naming/SKILL.md` | Когда создаёт или проверяет имя файла | Имена файлов и проверочные выражения |
| `schema/templates/*.md` | Когда создаёт страницу | Структура страниц, смысл и допустимые значения полей шапки |
| `schema/concept.md` | Никогда, кроме прямой просьбы пользователя прочитать или изменить его | Объяснение для человека |

Прочитанный навык остаётся в контексте до конца сессии, поэтому экономия получается в сессиях, где он не нужен: обычная консультация не тянет за собой правила ingest и lint.

Каждое правило записано в одном месте, остальные файлы на него ссылаются:

- правило для любого маршрута (безопасность, «никаких догадок», права на запись, формат ссылок) — только в `AGENTS.md`;
- имена файлов — только в навыке имён;
- структура страницы и допустимые значения полей шапки — только в шаблоне;
- как обновлять страницу при новом документе — только в навыке загрузки.

Этот файл (`concept.md`) — объяснение для человека; он пересказывает правила и не является их источником.
