# med-wiki: концепция LLM Wiki для медицинского консультанта

> **Канон.** Этот файл — норматив схемы медицинского консультанта. 
Корень репозитория содержит только системный промпт `AGENTS.md` и навигационный `README.md`. 
Детали записи, frontmatter, lint, шаблоны вынесены в папку `schema/`.

## 1. Цель
Персональная AI-powered база знаний о здоровье:
- ведение профиля пользователя с его суммарными медицинскими показателями (синтез);
- сохранение исходных скан-образов документов (`raw/images`) с возможностями прямого доступа по ссылкам;
- извлечение (OCR) информации из документов, обработка и сохранение синтеза;
- подготовка к визитам к врачам, помощь в составлении вопросов по диагнозам;
- ведение актуальных планов лечения, текущих заболеваний, диагнозов и анализов ("горячие" задачи);
- контроль хронических состояний и истории болезни;
- анализ динамики показателей, проведение консультаций по состояниям пациента;
- накопление внешних материалов (статьи, транскрипты, протоколы).

## 2. Паттерны и архитектура («Два слоя»)
Архитектура основана на паттернах LLM Wiki и Open Knowledge Format, а также механизмах Routing через индексные файлы и YAML-frontmatter.

- `raw/` = "Сырой" слой (immutable). Загруженные файлы, фото, PDF. Файлы здесь не изменяются, на них только ставятся ссылки.
- `wiki/` = "Синтезированный" слой (derived). Извлеченная информация и синтез в формате Markdown.

Агент **читает** wiki при общении, **пополняет** досье новыми фактами через операцию Ingest и **поддерживает согласованность** через операцию Lint. 

## 3. Конвенция именования (Naming Convention)
Все файлы в `raw/` и динамические записи в `wiki/` (например, визиты) строго подчиняются формату: `YYYY-MM-DD-<slug>.<ext>`.
Пример: `2023-10-15-blood-test.pdf` или `2023-10-20-cardiologist-visit.md`.

## 4. Файловая структура

<root>/
├── AGENTS.md                   # Системный промпт и правила для AI-агента
├── README.md                   # Навигация и описание для человека
├── raw/                        # Слой 1: Неизменяемые исходники
│   ├── docs/                   # PDF-статьи, медицинские карты, транскрипты
│   └── images/                 # Фотографии анализов, сканы, рентген-снимки
├── wiki/                       # Слой 2: Синтез и актуальные данные
│   ├── profile/                # Базовый контекст: статусы, аллергии, препараты
│   ├── diagnoses/              # Хронические и перенесенные заболевания
│   ├── metrics/                # Ряды показателей и динамика биометрии
│   ├── visits/                 # История посещений врачей и назначения
│   └── references/             # Конспекты статей, медицинских протоколов
└── schema/                     # Системные файлы конфигурации
    ├── concept.md              # Архитектура и паттерны базы (этот файл)
    └── templates/              # Шаблоны для генерации новых markdown-страниц

## 5. Индексные файлы и подпапки wiki
В корне каждой сущностной папки находится файл `_index.md`, содержащий сводную таблицу всех файлов папки и их актуальный статус. 

| Папка | Содержимое и структура |
|---|---|
| `profile/` | `_index.md` (сводка), `medications.md` (текущие препараты), `hot.md` (горячие задачи), `allergies.md`. |
| `diagnoses/` | Папки по нозологиям. Связаны через frontmatter с назначениями и показателями. |
| `metrics/` | Табличные данные динамики биометрии (например, `blood_tests.md`). |
| `visits/` | Протоколы приемов. Каждый визит — файл со ссылками на `raw/`. |
| `references/` | Сводки из внешних источников. Синтез статей. |

## 6. Сценарии потоков данных (Data Flows)

### A. Обновление профиля пользователя
Пользователь сообщает новые данные -> Агент (Maintainer) считывает `profile/medications.md` или `_index.md` -> Перезаписывает файл, фиксируя дату -> Проверяет конфликты.

### B. Ingest медицинского документа
Файл в `raw/` -> Проверка имени (Naming Convention) -> OCR -> Использование шаблона из `schema/templates/` -> Извлечение метрик -> Маршрутизация цифр в `wiki/metrics/`, назначений в `wiki/profile/` -> Обновление соответствующих `_index.md` -> Генерация summary.

### C. Жалоба или вопрос (Консультация)
Пользователь описывает симптомы -> Агент (Consultant) маршрутизирует поиск через `_index.md` -> Сканирует `profile/` и `diagnoses/` -> Сверяется с `references/` -> Выдает рекомендации и вопросы врачу. 

### D. Анализ трендов и актуальные задачи
Запрос статуса или показателя -> Агент собирает данные из `wiki/metrics/`, `profile/hot.md` и открытые назначения из `visits/` -> Формирует таблицу динамики и приоритезированный список действий.
