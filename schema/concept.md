# med-wiki: концепция LLM Wiki для медицинского консультанта

> **Канон для человека.** Как устроена база и зачем.
> Норматив для агента — `AGENTS.md` и навыки в `.agents/skills/` (раздел 9). При конфликте с этим файлом приоритет у них.
> Имена файлов — `.agents/skills/medwiki-file-naming/SKILL.md`. Шаблоны страниц — `schema/templates/`.

## 1. Цель

Персональная база знаний о здоровье, с которой работает AI-консультант:

- профиль и суммарные показатели — синтез, а не копия документов;
- оригиналы меддокументов и их распознанный текст — со ссылками из wiki;
- текущее состояние, открытые действия, история болезней;
- динамика показателей лаборатории;
- подготовка к визитам и вопросы врачам;
- внешние материалы (статьи, транскрипты) — отдельно от личных фактов.

Агент работает в двух ролях:

- **Консультант** (по умолчанию) — отвечает по досье. Сначала определяет тип вопроса, потом читает только нужные страницы.
- **Maintainer** — загружает документы (ingest), проверяет базу (lint), сохраняет итоги консультаций.

## 2. Два слоя

```
raw/   = входящие: оригинал документа, его распознанный текст, статья. Записанный файл не меняется.
wiki/  = что актуально сейчас: диагноз на всю историю, ряд показателя, схема, открытые действия.
```

Главный принцип: **картина состояния пользователя складывается только из `wiki/`.** `raw/` — сырьё для синтеза. Агент заглядывает в распознанный документ при ответе, только чтобы дать точную цитату врача или цифру, которой нет в wiki, но не строит по нему выводов в обход wiki.

Кто пишет в `raw/`: агент при загрузке документа сам выбирает имя по навыку имён, сохраняет оригинал в `raw/images/` и распознанный текст в `raw/docs/`. Существующие файлы в `raw/` агент не меняет. Исключение — ошибка распознавания, которую пользователь просит исправить по скану.

| Вопрос | Где ответ |
| --- | --- |
| Оригинал документа (скан, фото, PDF) | `raw/images/` |
| Что написано в конкретном анализе или заключении | `raw/docs/` — агент читает для цитаты, в wiki это не копируется |
| Как сейчас заболевание | `wiki/diagnoses/<slug>.md`, секция **Статус** |
| Как показатель менялся | `wiki/metrics/<slug>.md`, одна строка на дату |
| Загружался ли документ | `wiki/sources/_index.md` |
| Что принимаю | `wiki/profile/medications.md` |
| Что не сделано | `wiki/profile/open-actions.md` |
| Аллергии, направления наблюдения | `wiki/profile/` |
| Что решили на прошлой консультации | `wiki/notes/` |
| Чужой протокол, статья, транскрипт | `wiki/references/` — общие знания, не личный факт |

Загрузка документа **не создаёт** в wiki копию консультации, анализа или исследования. Документ остаётся файлом в `raw/docs/`. В wiki обновляются только сквозные сущности: статус диагноза и одна строка его истории, строка показателя, схема препаратов, открытые действия.

Отчёт, который пользователь просит сформировать (например, «паратгормон за 5 лет»), — это представление уже имеющихся данных, а не новый факт. Агент спрашивает, куда его сохранить, и не кладёт его ни в `wiki/`, ни в `raw/`, чтобы производный файл потом не стал «источником».

## 3. Именование

**Сущность в wiki** (диагноз, показатель, жалоба, справка) — имя без даты: одна страница на всю историю; даты живут внутри (история, динамика, текст жалобы).  
**Событие или снимок** (меддокумент, статья, сохранённый итог чата) — дата в имени файла.

| Что | Формат | Пример |
| --- | --- | --- |
| Распознанный меддокумент | `raw/docs/YYYY-MM-DD_<тип>.md` | `2025-11-22_lab-panel.md` |
| Оригинал меддокумента | `raw/images/` — то же имя, исходное расширение; страницы `-p1`, `-p2` | `2025-11-22_lab-panel-p1.jpg` |
| Статья или транскрипт | `raw/articles/YYYY-MM-DD-<slug>.md` | `2026-06-22-vitamin-d-overview.md` |
| Диагноз, показатель, жалоба, справка | `wiki/.../<slug>.md` | `wiki/diagnoses/insulin-resistance.md`, `wiki/symptoms/chest-pain.md` |
| Заметка (итог чата) | `wiki/notes/YYYY-MM-DD-<slug>.md` | `wiki/notes/2026-07-01-pth-trend.md` |

Дата в имени меддокумента — дата документа из его текста, не дата загрузки. Если даты в тексте нет — единственный случай, когда имя ждёт ответа пользователя: агент **предлагает** наиболее правдоподобную дату (из контекста чата или соседних файлов, если есть) и **одним вопросом** просит подтвердить или поправить. Имя нового файла иначе выбирает сам по навыку; существующие файлы не переименовывает. Точные правила — `.agents/skills/medwiki-file-naming/SKILL.md`.

Ссылки между файлами пишутся от корня репозитория с начальным `/` (например, `/raw/docs/2025-11-22_lab-panel.md`). Так ссылка не ломается, если страницу или шаблон перенести в другую папку.

## 4. Файловая структура

```
<корень>/
├── AGENTS.md            # ядро правил агента
├── .agents/skills/
│   ├── medwiki-ingest/  # загрузка документов и статей
│   ├── medwiki-lint/    # проверка базы
│   └── medwiki-file-naming/ # имена файлов (+ резолвер показателей)
├── raw/
│   ├── images/          # оригиналы меддокументов
│   ├── docs/            # распознанный текст меддокументов
│   └── articles/        # статьи и транскрипты
├── wiki/
│   ├── _index.md        # короткий маршрутизатор
│   ├── profile/
│   │   ├── _index.md
│   │   ├── me.md
│   │   ├── allergies.md
│   │   ├── medications.md
│   │   └── open-actions.md
│   ├── diagnoses/
│   ├── metrics/
│   ├── symptoms/
│   ├── references/
│   ├── sources/         # реестр загруженных документов (только _index.md)

└── schema/
    ├── concept.md
    ├── metric-synonyms.yaml  # канон имён показателей → slug
    └── templates/
```

## 5. Что лежит в wiki

| Папка или файл | Что это |
| --- | --- |
| `profile/me.md` | Кто пользователь, факторы риска, перенесённые операции (строка: дата, что сделано, ссылка), **активные направления** (кардиология, эндокринология и т.д.) со ссылками |
| `profile/allergies.md` | Аллергии |
| `profile/medications.md` | Только текущая схема. История приёма остаётся в `raw/docs/` |
| `profile/open-actions.md` | Незакрытые дела пользователя: визиты, обследования; при необходимости «начать приём» со ссылкой на схему. Не вопросы врачу и не дозы препаратов. Одна таблица, сортировка по сроку |
| `diagnoses/<slug>.md` | Одно заболевание на всю историю. **Статус** — как сейчас. **История** — таблица, новое сверху, каждая строка ссылается на `raw/docs/` |
| `metrics/_index.md` | Каталог страниц показателей (не ссылки на raw). Пополняется при загрузке панелей анализов |
| `metrics/<slug>.md` | Один показатель (число / качественный / пункт панели): динамика со ссылками на `raw/docs/` |
| `symptoms/` | Жалоба без меддокумента: одна страница на жалобу (`<slug>.md`), даты — в тексте |
| `sources/_index.md` | Реестр загруженных документов: ссылка на `raw/docs/` и дата загрузки. Строку ingest добавляет последним действием; нет строки — документ считается не загруженным. Нужен ingest и lint; для консультации не нужен |
| `references/` | Синтез статьи или транскрипта. Не личный факт без явной связи с диагнозом |
| `notes/` | Сохранённый итог чата с агентом («сохрани чат» / «сохрани обсуждение»): выводы, решения, вопросы врачу. Не путать с загрузкой меддокумента |
| `_index.md` в папке | Каталог: ссылка, одна строка описания, статус. Не копия тела страницы |

«Активные направления» в `me.md` — точка входа консультации. Как агент добавляет диагноз в направление и убирает `resolved` — в навыке загрузки (шаг 4); сверка на lint. Для каждого файла профиля и для каталогов есть шаблон в `schema/templates/`. Если нужного файла нет, агент создаёт его из шаблона и продолжает работу. Теги на странице диагноза не пусты (1–3 тега латиницей): по ним страницы отбираются при консультации.

Дела пользователя хранятся только в `wiki/profile/open-actions.md`. Агент не копирует список из документа, а синтезирует: группирует связанные обследования, формулирует задачу с глаголом, убирает дубли по смыслу и давно просроченное без подтверждения новым документом. Регулярный контроль — в **Мониторинг** на странице диагноза. Выполненное удаляется, а не помечается «сделано».

Показатели в `wiki/metrics/` — журнал лаборатории: при загрузке панели **каждый** показатель с именем и значением попадает на свою страницу (схема А). Полный текст панели всегда ещё и в `raw/docs/`. На консультации агент **не читает все метрики подряд**: только те, что нужны вопросу и активным направлениям, с «умным» окном динамики — как в `AGENTS.md` (раздел Metrics reading discipline): всегда последнее значение; раньше — если меняют картину; потолок по умолчанию при длинном ряде — **последние 2–3 года или последние 5 измерений**, что лучше отвечает вопросу. Одноразовый шум без связи с вопросом не поднимает. Синонимы (ТТГ / TSH / …) → один slug через `schema/metric-synonyms.yaml` и резолвер (только точное совпадение; Ratio / % / абсолют / разный биоматериал — разные slug). Маршрут K — **пересобрать / починить** динамику из raw, не условие первого появления показателя (первое появление — на ingest).

## 6. Как агент выбирает, что читать

До чтения досье агент относит запрос к одному маршруту.

| Код | Когда | Что читает |
| --- | --- | --- |
| **P** — личный факт | «мой», показатель, диагноз, дата анализа | каталог, нужные страницы; точную цифру или цитату — из `raw/docs/` |
| **H** — консультация | «можно ли мне», питание, тренировки, добавки, самочувствие | профиль, схема; аллергии — если вопрос про препарат, добавку или продукт; затем только нужное активное направление |
| **G** — общая теория | вопрос без привязки к пользователю | досье не читает; знания модели и веб |
| **O** — что не сделано | «что не закрыто», подготовка к визиту | сначала `open-actions.md` |
| **S** — сохранение (не меддокумент) | «сохрани чат / жалобу / отчёт», «сохрани в wiki» без меддокумента | по таблице в `AGENTS.md` §S: notes **или** symptoms **или** файл вне wiki (не всё сразу) |
| **I** — загрузка | «загрузи», «обработай», «сохрани» меддокумент или статью | ingest документа или статьи |
| **K** — пересобрать / починить метрику | «пересобери метрику», «почини динамику», устаревшее «добавь в ключевые» | пересборка страницы из всех `raw/docs/` |
| **L** — проверка | «проверь wiki», «lint» | вся структура wiki против `raw/docs/` |

Если по формулировке непонятно, что нужно, агент задаёт один уточняющий вопрос и не отвечает наугад. Запрос из нескольких целей («загрузи анализ и скажи, что изменилось») выполняется по порядку: сначала загрузка, потом консультация.

**«Сохрани документ» и «сохрани чат» — разные вещи.** Меддокумент (в том числе вставленный текстом без слова «документ») идёт в загрузку (**I**). Отличить от пересказа: в `AGENTS.md` — правило «≥2 признака» (дата; врач/клиника/бланк; структура заключения или таблица анализов; скан/«из выписки»). Пересказ и чат — **S**; цель внутри S — таблица в §S. «Сохрани в wiki» само по себе не выбирает ни I/S, ни цель внутри S.

Если в жалобе или документе есть признаки состояния, требующего срочной помощи, агент начинает ответ с рекомендации срочно обратиться к врачу.

## 7. Потоки

### Загрузка меддокумента

```
скан/фото/PDF ──► raw/images/  (оригинал; имя выбирает агент)
                     │  распознавание текста
                     ▼
                  raw/docs/    (текст как есть, нечитаемое помечено)
                     │  синтез
                     ▼
диагноз (статус + строка истории) · строка показателя · схема · аллергии · открытые действия
                     │
                     ▼
каталоги _index.md · отчёт в чат · консультация по изменениям · строка в реестре загруженных
```

Если пользователь даёт готовый текст, шаг с оригиналом пропускается. Если файл уже лежит в `raw/docs/`, он берётся как есть: имя не проверяется и не меняется, а загружался ли он, определяет реестр `wiki/sources/_index.md` (строки нет — загружаем, есть — пропускаем). Документ об операции или процедуре даёт строку в «Перенесённых операциях» `me.md`; страница диагноза создаётся только для состояния, названного в клиническом тексте. Сомнительные после распознавания даты, дозы и значения, а также неясные рекомендации агент собирает и задаёт **одним блоком** в конце загрузки.

### Жалоба или вопрос

Маршрут из раздела 6. Ответ со ссылкой на файл. Чего в источниках нет — не утверждать. Новую жалобу агент предлагает записать в `wiki/symptoms/`.

### Статья или транскрипт

Файл в `raw/articles/`, синтез в `wiki/references/`. В ответ о личном анализе или диагнозе этот слой не подставляется вместо досье.

### Lint

Запускает пользователь. Агент сверяет wiki с последними документами и реестр загруженных с `raw/docs/`, чинит ссылки и каталоги на месте, пересобирает открытые действия и пишет отчёт в чат. Неверные имена файлов и противоречия между двумя документами агент только перечисляет — решает пользователь. Файлы отчётов в wiki не создаются, пояснения терминов в страницы досье не дописываются.

## 8. Рост

Wiki растёт медленнее `raw/`. Не копировать тела консультаций. Страница показателя появляется при ingest панели (схема А), а не «по списку ключевых». Длинный сохранённый ответ (больше примерно 4 КБ) класть в `references/`, в `notes/` оставлять указатель.

## 9. Как устроены инструкции агента

Инструкции агента занимают место в контексте модели — в тексте, который модель видит при каждом ответе. Чем больше постоянная часть, тем дороже каждый шаг. Поэтому инструкции разделены:

| Файл | Когда агент его читает | Что внутри |
| --- | --- | --- |
| `AGENTS.md` | Всегда, с начала сессии | Роль, безопасность, права на запись, два слоя, выбор маршрута, консультация, сохранение |
| `.agents/skills/medwiki-ingest/SKILL.md` | Только при загрузке документа или статьи | Шаги ingest, страницы показателей, пакетная загрузка |
| `.agents/skills/medwiki-lint/SKILL.md` | Только при проверке базы | Список проверок lint |
| `.agents/skills/medwiki-file-naming/SKILL.md` | Когда создаёт или проверяет имя файла | Имена файлов и проверочные выражения |
| `schema/templates/*.md` | Когда создаёт страницу | Структура страниц, смысл и допустимые значения полей шапки |
| `schema/concept.md` | Никогда, кроме прямой просьбы пользователя прочитать или изменить его | Объяснение для человека |

Прочитанный навык остаётся в контексте до конца сессии, поэтому экономия получается в сессиях, где он не нужен: обычная консультация не тянет за собой правила ingest и lint.

Каждое правило записано в одном месте, остальные файлы на него ссылаются:

- правило для любого маршрута (безопасность, «никаких догадок», права на запись, формат ссылок) — только в `AGENTS.md`;
- имена файлов — только в навыке имён;
- структура страницы и допустимые значения полей шапки — только в шаблоне;
- как обновлять страницу при новом документе — только в навыке загрузки.

Этот файл (`concept.md`) — объяснение для человека; он пересказывает правила и не является их источником.
